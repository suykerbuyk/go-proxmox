# Migrating to v0.8.2

## Deleting a cloud-init VM can now refuse

`VirtualMachine.Delete` and `UnmountCloudInitISO` remove the VM's cloud-init
ISO from whichever iso-capable storage holds it. Before v0.8.2, a failed
lookup on a storage was treated as "not on this storage". If that storage
held the ISO, the VM was deleted and the ISO was left behind.

When a lookup fails, the storage's content listing now decides. `Delete`
returns an error, and sends no VM DELETE, when a lookup fails and:

- the listing shows the ISO, so the lookup failed on something that exists;
- the listing cannot be read, for example an unreachable NFS mount that is
  still enabled in the storage configuration;
- the listing comes back with no data at all (`{"data":null}`).

This is deliberate: deleting the VM cannot be undone, and the storage that
could not be confirmed may hold the ISO. Disable a storage that is
permanently unreachable, or fix it, then retry the delete.

Unchanged: a lookup that finds the ISO deletes it, and an ISO that neither
the lookup nor the listing finds is treated as already gone.
